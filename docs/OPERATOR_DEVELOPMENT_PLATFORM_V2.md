# Operator Development Platform v2

## Core loop

Learn → Execute → Reflect → Challenge → Achieve → Analyse → Improve.

## Engines

- **Learning** records concepts acquired from providers, books, videos and local courses.
- **Execution** records what was built, practised, performed or delivered.
- **Reflection** records meaning, lessons, identity changes and epiphanies.
- **Challenges** define bounded tests with success criteria.
- **Achievements** recognise verified milestones.
- **Stats** aggregate development across CON, INT, STR, DEX, DISC, WILL and SPIRIT.
- **History** provides an immutable event timeline.
- **Analytics** exposes patterns without replacing human judgement.

## Shared hierarchy

Main Stat → Domain → Category → Capability → Concept.

Learning is stat-neutral. A learning event may distribute one XP award across multiple concepts and stats. Execution records do not automatically claim mastery: they create evidence that may later be verified or mapped to progression.

## Repository boundaries

- `zeroGravity-rnd`: learning models, experiments, project evidence, Operator core and Zero World research.
- `zero-command-system`: user interface, APIs and orchestration.
- `zeroGravity`: business operations, website, portfolio, brand and commercial outputs.

Real private journals, health records and financial details should remain in local ignored databases.
